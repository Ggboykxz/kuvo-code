# Kuvo Code 0.5.72 — the title bar keeps its room, the terminal says why, and a model reaches the engine

- **The window knows its shell by the bridge, not by its address.** The page found the
  shell in `?shell=1` and the terminal's port in `?terminalPort=…`; a Back — the mouse's own
  button, or Alt+Left — took both away, and with them the title bar's room for the window's
  controls, so the page's buttons slid under them. Both travel by the bridge now
  (`preload.js`: `isShell`, and the port asked of the shell), and the shell pins its page:
  Back and Forward are ignored, and the window cannot leave the harness (`main.js`).
- **A terminal that cannot start says why.** The shell sends the reason with the close — no
  node-pty in this build, or a shell that would not spawn — and the panel shows it where the
  terminal would be, instead of a bare "Terminal closed." node-pty is a required dependency
  now, so a release that cannot build it fails rather than shipping a terminal that never
  starts.
- **A chosen model goes to the engine as its Model.ref.** The picker posted the shorthand
  `provider/id`, and the engine answered *Expected Model.Ref at ["model"]*. It sends the
  object the Mac sends — `{ providerID, id }` (`OpenCodeKit/Models/Common.swift:70`,
  `OpenCodeAPI.swift:473-476`), an id's own slashes kept in it — and the picker shows the
  new model at once, putting the old one back if the engine refuses
  (`SessionModel.swift:1333-1341`). The "engine's choice" row is gone: the Mac's picker has
  no such row, and the engine no call to clear a model.

217 unit tests pass — the model's shape proved without an engine, and the shell's seams and
the Model.ref pinned by contracts — `tsc --noEmit` is clean, the page builds, and the live
page against the real engine passes in Chromium, twice.

Windows 10/11, x64. The installer and the portable build are unsigned; Windows may warn on
first run.
