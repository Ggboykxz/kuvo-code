# 0.7.3 — the update installs

0.7.3 is a fix release for the Windows client. The update check could find a
new version and download it, and then the update stopped: the installer was
written to a fixed name in the temporary folder, read whole into memory, and
opened with whatever program Windows had for it. On a machine behind a proxy,
or one where Windows still held the previous attempt's file, nothing happened
and nothing said why.

## What changed

### The check goes through Windows' network, not Node's

- The check and the download use Electron's network stack, which reads this
  computer's proxy settings and its certificate store. A machine whose browser
  reaches GitHub reaches it here too.
- When the GitHub API is limited or blocked, the releases feed answers instead.
  It needs no token and has no hourly limit, and the installer's name is ours,
  so the tag is enough to find it.

### The download lands, and is checked

- The installer streams to `%APPDATA%\Kuvo Code\updates` as it arrives, under a
  name of its own for every attempt, so a second try cannot collide with a file
  Windows still has open.
- The bytes are checked before anything runs: the length the server promised, a
  40 MB floor, and the `MZ` every Windows program starts with. A half-written
  file is removed rather than left for Windows to try.
- The taskbar and the tray show how far it has got. Installers an earlier
  attempt left behind are swept after a day.

### It says what happened

- The installer starts on its own, detached, and Kuvo Code quits so it can
  replace the files. If Windows refuses the direct start, the shell asks it to
  open the file, as a double-click would.
- Every attempt is written to `update.log` beside the app's settings. A quiet
  check that fails used to say nothing on purpose; now the log says why, and
  Settings › General shows the last failure with a button to the log.
- Windows shows Kuvo Code's notifications again: the shell registers the same
  Application User Model ID as the installer's shortcut.
- Settings › General shows the version that is running, **Check Now**, and
  **Install** when a version is waiting. The app menu and the tray carry
  **Update to X…**, and the tray says **Update failed: …** when it did.

### The settings page tells the truth

- The note no longer says updates are signed. They are not yet: the installer is
  unsigned, and Windows may warn before it runs.
- The automatic-update timer reads the setting each time it fires, so turning
  updates on in Settings starts the checks without a restart.

## Tests

- New `windows/update-install.test.mjs`: a name is a file's own, a download
  streams and reports progress, two attempts get two files, a 404 leaves
  nothing, a page and a too-small file are removed, a connection that stops
  early is an error, the installer starts detached, and the sweep keeps today's
  installer and the one in hand.
- `windows/update-check.test.mjs` covers the releases feed, the newest of ours,
  and the words a failure is reported in.
- `node windows/tools/verify.mjs`: tests, contrast, lint, typecheck and page
  build all green locally.

The Windows CI run on the release tag is the gate for the assets below.

## Not in this release

- The panel's browser and its saved passwords.
- The phone link, sessions on remote machines, and running sessions through
  coding agents.
- Creating and editing bots on Windows.

These are tracked in `docs/ROADMAP.md`.
