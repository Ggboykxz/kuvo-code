# Kuvo Code 0.5.76 — a picture the model can see, and the viewer that looks at it

- **A picture attached to a message now reaches the engine.** The port sent the file in
  the page's own shape, where the engine takes a URI and a name (`OpenCodeKit`'s
  `PromptFile`, `OpenCodeAPI.swift:437-445`), and the harness threw away the files that
  were not already on disk: a picture was never sent, and the message was refused. The
  files go as the Mac sends them now — a data URI for what the page read, a file's own
  path for what was on disk — and a picture alone is a message, as it is on the Mac
  (`Composer.swift:109-113`).
- **The picture stays in the conversation** when the message is delivered, and it shows at
  once as it is sent.
- **The viewer moves as the Mac's does** (`ImageViewer.swift:22, 28, 40`): it fades in over
  160 ms and out over 140, the window under it dims to 30 % over 150 ms and is out of
  reach of a click, the scrim is the Mac's black at 62 %, and the picture comes in from
  0.94 of its size. A double-click zooms it, as the Mac's does.

228 unit tests pass — the viewer's own timings and the shape of a file, proved without an
engine — `tsc --noEmit` is clean, the page builds, and the live page against the real
engine passes in Chromium, twice.

Windows 10/11, x64. The installer and the portable build are unsigned; Windows may warn on
first run.
